# 한본어 입력기

한본어를 선택했을 때 Windows 입력 표시기의 브랜드 아이콘은 **HB**입니다. 입력기 DLL에 다중 크기 아이콘을 포함하고 시스템 트레이 표시 지원을 등록합니다. 상주 업데이터의 트레이 아이콘은 위쪽 화살표이며 입력기의 HB 아이콘과 구분됩니다. `ime-tool.exe --branding <입력기 DLL 경로>`는 아이콘 추출과 표시 지원 등록을 확인합니다.

Windows TSF 입력기입니다. 두벌식 한글 키 입력을 조합하고, 입력한 발음을 문자 규칙으로 히라가나로 변환합니다. Space를 누르면 PC에 설치된 Microsoft 일본어 IME의 `IFELanguage` 변환 엔진으로 후보를 가져옵니다. Microsoft 사전 파일을 복사하거나 별도 일본어 단어 사전을 포함하지 않습니다.

**단어 프리셋, 문구별 예외, 장음 추측, 조사 자동 치환이 없습니다.**

| 입력 | 가나 읽기 |
| --- | --- |
| 아리가토 | ありがと |
| 아리가토우 | ありがとう |
| 곤니치와 | ごんにちわ |
| 콘니치하 | こんにちは |
| 니홍고 | にほんご |
| 갓코우 | がっこう |
| 쿄우 | きょう |

## 사용

Win+Space에서 **한본어 입력기**를 선택합니다. 일본어 언어에 등록됩니다. 한글 두벌식으로 발음을 입력하면 조합 중인 가나가 표시됩니다.

| 키 | 동작 |
| --- | --- |
| Space | Microsoft IME 후보 가져오기 / 다음 후보 |
| ↑ ↓ / ← → | 후보 이동 |
| PageUp / PageDown | 후보 9개씩 이동 |
| 1–9 | 현재 페이지 후보 선택·확정 |
| Enter | 현재 가나 또는 선택한 후보 확정 |
| Escape | 후보 선택 해제, 한 번 더 누르면 조합 취소 |
| Backspace | 입력한 마지막 한글 자모 삭제 |
| F6 / F7 | 히라가나 / 가타카나 |
| - | 장음 기호 ー 입력 (같은 조합 안에 유지) |
| Win+Space | 다른 Windows 입력기로 전환 |

선택된 한자 후보에 이어 글자를 입력하면 후보를 확정한 뒤 새 조합을 시작합니다. 문장부호 등은 현재 조합을 확정한 뒤 앱에 전달합니다.

## 발음 규칙

초성 ㄱ/ㄷ/ㅂ/ㅈ은 각각 が/だ/ば/ざ 행, ㅋ·ㄲ/ㅌ·ㄸ/ㅍ·ㅃ/ㅊ은 각각 か/た/ぱ/ちゃ 행을 사용합니다. ㄴ·ㄹ·ㅁ·ㅅ·ㅇ·ㅎ은 な·ら·ま·さ·あ·は 행입니다. ㅆ은 さ 행, ㅉ은 ざ 행입니다. 단어의 위치와 관계없이 같은 규칙을 적용합니다.

ㅏ·ㅣ·ㅜ·ㅔ·ㅗ는 a·i·u·e·o입니다. 한국어 근사 발음에 따라 ㅐ→e, ㅓ→o, ㅡ→u로 처리합니다. ㅑ·ㅕ·ㅛ·ㅠ는 작은 ゃ·ょ·ょ·ゅ를 붙인 요음, 초성 ㅇ에서는 や·よ·よ·ゆ입니다. ㅘ·ㅝ·ㅟ는 わ·うぉ·うぃ 계열입니다. ㅒ·ㅖ·ㅙ·ㅚ·ㅞ는 e, ㅢ는 i로 처리합니다.

받침 ㄴ·ㅁ·ㅇ은 ん, ㄹ은 る, 나머지 받침은 っ입니다. 겹받침도 마지막 규칙을 적용합니다. 아직 조합 중인 자모는 그대로 표시하며, 다음 모음 입력 시 재조합합니다. 한글 입력으로 일본어 발음을 완전히 구별할 수 없으므로 이 문자 규칙을 명시적으로 사용합니다. 장음은 `오우`, `에이`처럼 직접 입력하거나 `-`로 `ー`를 입력합니다. `코-히-`는 `こーひー` 한 조합으로 유지됩니다.

Windows IME의 한자 변환은 Space를 누를 때만 수행합니다. 가나 읽기는 자체적으로 단어를 교정하지 않지만, Microsoft IME가 반환하는 한자 후보에는 엔진의 해석이 반영됩니다. F6로 입력한 가나를 유지할 수 있습니다.

## 설치

1. [최신 릴리스](https://github.com/MapleYoil/HanBonGo/releases/latest)에서 HanBonGo-windows.zip을 다운로드합니다.
2. ZIP 파일의 압축을 풉니다.
3. 압축을 푼 폴더의 **설치.cmd**를 더블클릭합니다.
4. 관리자 권한 확인 창에서 **예**를 누릅니다.
5. 완료 안내가 뜨면 **Win + Space**로 한본어 입력기를 선택합니다.

삭제는 시작 메뉴의 **한본어 입력기 → 제거**를 실행합니다.

## 소스 빌드

필요: Windows 10/11 x64, Microsoft 일본어 IME, Visual Studio 2022 C++ 도구, Windows SDK, CMake.

```powershell
cd HanBonGo
.\scripts\build.ps1
```

`build.ps1`은 검사 성공 후 재설치와 새 키보드 전환까지 자동 실행합니다. Windows TSF 시스템 등록에 필요한 관리자 권한 확인 창이 표시될 수 있습니다. 중간 빌드만 하려면 `build.ps1 -SkipInstall`을 사용합니다. 이미 빌드한 결과를 다시 설치·전환하려면 일반 PowerShell에서 다음을 실행합니다.

```powershell
cd HanBonGo
.\scripts\update.ps1
```

64비트·32비트 DLL과 실행 도구를 `C:\Program Files\HanBonGo\<빌드 해시>`에 설치하고 COM 클래스, TSF 일본어 프로필, 키보드 카테고리를 등록합니다. 입력기 소스가 바뀌면 COM ID도 새로 생성하여 실행 중인 프로그램이 캐시한 이전 입력기와 구분합니다. 이전 프로필을 제거하고 사용자 키보드 목록·기본 입력기·일본어 기본 프로필을 새 버전으로 설정한 뒤 `ActivateProfile`로 전환합니다. 현재 편집 창에도 일본어 입력 언어 변경을 요청합니다. 같은 소스를 재설치할 때는 동일한 ID를 유지합니다. 현재 설치 경로는 `active-install.json`에 기록됩니다. 프로그램 강제 종료나 자동 로그아웃은 하지 않습니다. 입력 언어 변경을 거부하는 프로그램에서는 Win+Space로 새 입력기를 선택합니다.

삭제는 시작 메뉴의 **한본어 입력기 → 제거**를 실행합니다.

## 검증

`build.ps1`은 두 아키텍처에서 자모 조합·가나 변환을 검사하고, 실제 Microsoft IME가 `にほんご`를 `日本語`로 변환하는지 확인합니다.

`--integration`은 TSF 문서·편집 잠금·키 이벤트·조합 범위·확정을 검사하기 위한 실험용 진단입니다. 현재 이 PC에서는 자동 활성화 후 `Test key rejected`가 발생하여 이 진단은 통과하지 않았습니다. 빌드 시 실행하는 검사는 자모·가나 변환 및 실제 Microsoft IME 사전 호출이며, 일반 앱에서의 입력 동작 검증과는 구분됩니다. 아래 진단은 잠시 테스트 창을 열고 해당 프로세스의 입력 언어를 일본어로 전환합니다.

```powershell
$installed = (Get-Content 'C:\Program Files\HanBonGo\active-install.json' -Raw | ConvertFrom-Json).versionRoot
& "$installed\x64\ime-tool.exe" --integration "$installed\x64\HangulJpIME.dll"
& "$installed\Win32\ime-tool.exe" --integration "$installed\Win32\HangulJpIME.dll"
```

현재 구현은 기본 데스크톱 TSF 입력기입니다. Microsoft 일본어 IME의 최신 후보 UI, 문절별 편집, 사용자 학습 동작을 그대로 복제하지 않으며 Store/UWP·게임·특수 편집기의 호환성은 별도 확인이 필요합니다. DLL은 서명하지 않은 개발 빌드입니다.

사용자용 설치는 Windows `input.dll`의 `InstallLayoutOrTip`으로 수행합니다. 업데이트는 이 호출 후 `EnumEnabledLayoutOrTip` 및 `IsEnabledLanguageProfile`로 등록·활성 상태를 검사합니다. `ime-tool.exe --user-status`로 같은 상태를 조회할 수 있습니다. 열린 설정 페이지는 다시 진입해야 표시가 갱신될 수 있습니다.

## 업데이터와 제거 프로그램

설치 시 시작 메뉴의 한본어 입력기 폴더에 업데이터와 제거 바로가기를 등록합니다. 업데이터는 HanBonGo.Updater.exe라는 트레이 전용 프로그램입니다. 콘솔이나 PowerShell 업데이터 창을 열지 않습니다. Windows 로그인 시 자동 실행되고, 실행 직후와 설정한 주기마다 공개 GitHub Releases를 확인합니다.

설정 창은 없고 트레이 우클릭 메뉴에서 직접 Windows 시작 시 실행, 확인 주기(30분·1시간·3시간·6시간·12시간·하루), 새 버전 알림, 자동 설치를 변경합니다. 기본 주기는 6시간, 알림은 켜짐, 자동 설치는 꺼짐입니다. 새 버전 알림을 누르면 설치를 시작합니다. 크레딧 하위 메뉴에는 개발자 MapleYoil, Microsoft 일본어 IME, 클릭하면 브라우저로 여는 GitHub 주소를 표시합니다.

설정은 사용자 LocalAppData/HanBonGo/settings.json에 저장되고 로그는 같은 폴더의 updater.log에 기록됩니다. 시작 실행을 끈 선택은 다음 업데이트에서도 유지합니다. 메뉴는 트레이 아이콘을 우클릭할 때만 열립니다. 수동 실행이나 더블클릭으로 메뉴가 열리지 않으며, 이미 실행 중이면 추가 실행은 종료됩니다. 종료는 입력기가 아닌 업데이터만 종료합니다.

업데이트 원본은 https://github.com/MapleYoil/HanBonGo 의 공개 GitHub Releases입니다. 안정 버전 태그(v0.1.1 등)로 릴리스를 만들고 dist/HanBonGo-windows.zip을 자산으로 첨부하면 확인합니다. version.json의 버전과 태그를 맞추어야 합니다. GitHub SHA-256 digest로 다운로드를 검증합니다. 설치에 필요한 Windows 관리자 권한 확인은 표시될 수 있으며, 내부 설치 작업은 숨겨진 PowerShell 설치 도구를 사용합니다.

배포 ZIP에는 32/64비트 입력기 바이너리와 트레이 업데이터가 들어 있습니다. 설치할 PC에는 Visual Studio나 CMake가 필요하지 않으며, Windows에 포함된 .NET Framework 4.8을 사용합니다. ZIP을 풀어 **설치.cmd**를 더블클릭하면 설치됩니다. 설치된 관리 도구는 Program Files/HanBonGo에 배치되어 원본 소스 폴더 없이 동작합니다.
